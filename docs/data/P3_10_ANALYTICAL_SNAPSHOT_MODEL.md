# P3.10 Analytical Snapshot Model

## Purpose

This document defines the analytical snapshot model for governed reports, dashboards, exports, institutional evidence, and future research.

## Status

Backend production readiness: BLOCKED_PENDING_REAL_EVIDENCE

## Snapshot principle

An analytical snapshot is a reproducible, time-bounded representation of approved operational data.

It is not the operational source of truth.

SQL Server is the operational source of truth.

| Field | Required | Purpose |
|---|---:|---|
| snapshot id | Yes | Stable identifier |
| snapshot type | Yes | operational, tactical, strategic, research |
| organization id | Yes | Institutional boundary |
| source time range | Yes | Reproducibility |
| source filters | Yes | Reproducibility |
| generated at | Yes | Traceability |
| generated by | Yes | Actor |
| pipeline id | Yes | Pipeline traceability |
| pipeline version | Yes | Reproducibility |
| source system | Yes | Source traceability |
| source tables or views | Yes | Source lineage |
| input record count | Yes | Quality control |
| output record count | Yes | Quality control |
| rejected records | Yes | Data quality |
| quarantine count | Yes | Data quality |

| audit trail reference | Yes | Auditability |

## Snapshot types

| Type | Purpose |
|---|---|
| operational snapshot | Daily review of brigades, encounters, services, and patients |
| tactical snapshot | Program management and service planning |
| strategic snapshot | Direction, board, donor, and institutional reporting |
| research snapshot | ODS, impact, statistical, causal, Bayesian, or academic analysis |
| quality snapshot | Completeness, rejected records, quarantine, validation, and correction analysis |

## Snapshot content boundaries

Snapshots may include:

- aggregate counts.
- encounter counts.
- service counts.
- brigade counts.
- consent counts.
- correction counts.
- rejected records count.
- quarantine count.
- export counts.
- dashboard dataset references.
- data quality summaries.
- longitudinal aggregate indicators.

Snapshots must avoid unnecessary:

- raw patient names.
- raw clinical notes.
- unrestricted identifiers.
- credentials.
- secrets.
- unredacted sensitive data.

No secrets in repository.

## Reproducibility requirements

A snapshot must be reproducible from:

- pipeline id.
- pipeline version.
- source time range.
- source filters.
- organization id.
- source view or source table reference.
- generated at timestamp.
- audit trail reference.

## Longitudinal compatibility

Snapshots must preserve compatibility with:

- patient timeline.
- consent timeline.
- encounter timeline.
- clinical timeline.
- correction timeline.
- merge and deduplication timeline.
- audit trail.

## Correction handling

When source operational records are corrected:

- prior snapshots must not be silently overwritten.
- new snapshots must represent the corrected state.
- correction event must remain auditable.
- snapshot lineage must show which data version was used.

No silent overwrite is allowed.

## Snapshot conclusion

Analytical snapshots are governed evidence artifacts, not operational truth.
