# P3.10 Report and Export Governance

## Purpose

This document defines report and export governance for operational, tactical, strategic, and research outputs.

## Status

Backend production readiness: BLOCKED_PENDING_REAL_EVIDENCE

## Export principle

Every report export must be auditable, scoped, minimized, and reproducible.

No export may bypass audit trail.

## Export types

| Export type | Purpose |
|---|---|
| operational CSV/XLSX | Daily or periodic operational review |
| dashboard dataset | Approved dataset for visual dashboards |
| institutional evidence package | Sanitized package for leadership, partners, or donors |
| quality report | Completeness, validation, rejected records, quarantine |
| research dataset | Governed and minimized dataset for analysis |

## Required export metadata

Every export must preserve:

- export id
- export type
- requested by
- generated by
- organization id
- request id
- correlation id
- generated at
- source time range
- source filters
- source snapshot id when applicable
- row count
- column count
- sensitive field classification
- minimization decision
- audit trail reference

## Export governance rules

Required rules:

- No secrets in repository.
- No ungoverned patient-level export.
- No unrestricted raw clinical note export.
- No cross-organization export without authorization.
- No report export without audit trail.
- No dashboard dataset without organization id.
- No export that bypasses consent boundaries.
- No export that silently modifies source data.

## Export approval classes

| Class | Scope | Governance |
|---|---|---|
| low risk aggregate | Counts and summaries | Standard audit trail |
| operational patient-level | Needed for operations | Role-based access and audit trail |
| sensitive clinical | High sensitivity | Explicit approval and minimization |
| external institutional | Leadership, donors, partners | Sanitization and aggregate preference |
| research | Statistical/ODS analysis | Privacy review and minimization |

## CSV/XLSX baseline

CSV/XLSX exports must include:

- file generation timestamp.
- organization scope.
- source time range.
- report type.
- sanitized evidence id or export id.
- row count.
- column count.
- audit trail reference.

## Dashboard dataset baseline

Dashboard datasets must include:

- dataset id.
- dashboard name.
- source snapshot id.
- refresh timestamp.
- organization id.
- metric definitions.
- data quality summary.
- audit trail reference.

## Evidence package baseline

Institutional evidence packages must include:

- evidence package id.
- purpose.
- owner.
- source snapshot ids.
- source report ids.
- generated at.
- approved by when required.
- audit trail reference.
- privacy minimization statement.

## Report and export conclusion

Reports and exports are controlled outputs, not uncontrolled file dumps.
